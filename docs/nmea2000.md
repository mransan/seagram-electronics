# NMEA 2000 Protocol Specification and Engineering Guide

This comprehensive reference document covers the electrical architecture,
Controller Area Network (CAN bus) signaling, ISO 11898 physical layer, SAE
J1939 protocol framing, Parameter Group Numbers (PGNs), address claim
arbitration, network topology, power distribution rules (Load Equivalency
Numbers), and modern interfacing strategies for marine electronics conforming
to the [NMEA 2000 (IEC 61162-3)][ref-nmea2000-main] standard.

---

## 1. Physical Architecture and Cable Infrastructure

NMEA 2000 is a serialized marine data bus standard governed by the [National
Marine Electronics Association (NMEA)][ref-nmea-org] and internationally
standardized under [IEC 61162-3][ref-iec-61162-3]. Unlike legacy single-ended
serial protocols (such as NMEA 0183 or SeaTalk1), NMEA 2000 is built on top of
the balanced differential [Controller Area Network (CAN)][ref-bosch-can]
physical and data-link standard, specifically conforming to [ISO
11898-2][ref-iso-11898-2].

The network utilizes a trunk-and-drop ("backbone and spur") bus topology where
DC power (+9V to +16V nominal 12V) and balanced differential serial data travel
together inside a shielded 5-conductor cable assembly based on the industrial
[DeviceNet physical layer specification][ref-devicenet-spec].

### 1.1 Wire Color Mapping and Functional Allocation

Standard NMEA 2000 cabling contains two twisted pairs plus an overall shield
drain wire, organized as follows:

| Wire Color | Signal Label | Pin # (Micro-C) | Electrical Function |
| :--- | :--- | :--- | :--- |
| **Bare / Drain** | **Shield** | Pin 1 | Braided / Foil Cable Shield & RF Ground Drain |
| **Red** | **NET-S** | Pin 2 | Network Power Supply (+12V DC nominal Rail) |
| **Black** | **NET-C** | Pin 3 | Network Power Return / Ground (0V Reference) |
| **White** | **NET-H** | Pin 4 | CAN High Differential Data Line ($V_H$) |
| **Blue** | **NET-L** | Pin 5 | CAN Low Differential Data Line ($V_L$) |

```
+-------------------------------------------------------------------------+
|                  NMEA 2000 5-Wire Cable Infrastructure                  |
|                                                                         |
|  [ Red Wire ]    NET-S (+12V DC Power Rail) ------------------------->  |
|  [ Black Wire ]  NET-C (0V System DC Return) ------------------------>  |
|  [ White Wire ]  NET-H (CAN_H Differential Signal) <=================>  |
|  [ Blue Wire ]   NET-L (CAN_L Differential Signal) <=================>  |
|  [ Bare Drain ]  Shield (RF / Drain Ground tied at single point) ----->  |
+-------------------------------------------------------------------------+
```

As detailed in [Actisense's NMEA 2000 Networking Guide][ref-actisense-guide]
and [Maretron NMEA 2000 Cable Technical Guidelines][ref-maretron-cabling], the
power pair (Red/Black) and data pair (White/Blue) are individually twisted and
shielded to prevent cross-talk between the switching DC loads and sensitive
high-speed data transitions.

### 1.2 Cable Categories and Hardware Dimensions

The standard defines three primary cable classifications:

1. **Micro Cable (Light Cable):**
   * Most common in leisure marine craft under 15 m (50 ft).
   * Data conductors: 24 AWG ($0.20\,\text{mm}^2$); Power conductors: 22 AWG
     ($0.32\,\text{mm}^2$).
   * Outside diameter: ~6.0 mm.
   * Maximum continuous backbone length: **100 meters (328 ft)**.
   * Maximum current capacity: **3 Amps** (continuous DC).
2. **Mid Cable:**
   * Used for longer runs on mid-sized motor yachts and cruising sailboats.
   * Data conductors: 20 AWG ($0.52\,\text{mm}^2$); Power conductors: 16 AWG
     ($1.31\,\text{mm}^2$).
   * Outside diameter: ~8.4 mm.
   * Maximum continuous backbone length: **100 meters (328 ft)**.
   * Maximum current capacity: **4 Amps**.
3. **Mini Cable (Heavy Cable):**
   * Used for commercial vessels, large luxury yachts, and long masthead runs.
   * Data conductors: 18 AWG ($0.82\,\text{mm}^2$); Power conductors: 15 AWG
     ($1.65\,\text{mm}^2$).
   * Outside diameter: ~12.2 mm.
   * Maximum continuous backbone length: **200 meters (656 ft)**.
   * Maximum current capacity: **8 Amps**.

### 1.3 Connector Families and Proprietary Form Factors

NMEA 2000 enforces circular, waterproof (IP67 / IP68) screw-collar connectors.
While electrically compatible across brands, marine manufacturers employ
differing mechanical connector variants:

* **Micro-C (DeviceNet M12 5-pin):** The universal standard connector used by
  Garmin, Navico (Simrad, B&G, Lowrance), Furuno, Maretron, and Actisense.
  Features a keyed M12 thread.
* **Raymarine SeaTalkng (STng):** A proprietary keyed connector format with
  color-coded collars:
  * *Blue collars & blue striped cable:* Dedicated backbone trunk links.
  * *White collars & white striped cable:* Spur / drop cables to instruments.
  * *Yellow collars:* Bridging ports (e.g., [Raymarine E22158
    Converter][ref-e22158-guide]).
  * *Black collars:* Backbone termination plugs.
  * Electrically, SeaTalkng is 100% standard NMEA 2000 (CAN bus) and can be
    adapted to standard Micro-C using passive adapter cables (e.g., [Raymarine
    A06045 / A06075][ref-raymarine-adapters]).
* **Simrad SimNet:** An older Navico proprietary push-in slimline connector
  found on legacy B&G, Simrad, and Lowrance systems. Can be converted to
  Micro-C using passive SimNet-to-Micro-C adapter cables.
* **Mini (DeviceNet 7/8" Mini-Change):** Heavy-duty 5-pin screw connectors used
  on heavy backbone cable runs.

### 1.4 Network Topology and Installation Rules

NMEA 2000 mandates a strict **linear trunk-and-drop** topology. Failure to
follow topology limits introduces signal reflections and data collisions:

```
Terminator                                                            Terminator
 [120R]                                                                 [120R]
   |                                                                      |
   +======[T-Connector]========[T-Connector]========[T-Connector]=========+
               |                    |                    |
          Spur Cable           Spur Cable           Power Tap
         (Max 6 m)            (Max 6 m)             (12V DC)
               |                    |
          [Sensor / GPS]       [Chartplotter]
```

1. **Backbone Continuity:** The backbone must form a single, continuous trunk
   line running throughout the vessel. Daisy-chaining from one instrument's
   spur port to another is strictly prohibited by the specification.
2. **Spur (Drop) Cable Lengths:**
   * Maximum individual spur length: **6 meters (20 feet)**.
   * Maximum cumulative spur length: **78 meters (256 feet)** across the entire
     network.
3. **Termination Resistors:** Exactly two $120\,\Omega$ termination resistors
   must be installed at the two physical extreme ends of the backbone.
   Intermediate drops or open ends must never include terminators.

### 1.5 Clustering Devices at a Remote Location (Cockpit Instrument Pod)

A very common marine design requirement is connecting multiple instruments
located in a cluster—such as a cockpit helm pod or mast base with 3
displays—back to the vessel's primary backbone below decks via a single
physical cable run.

In standard NMEA 2000, **direct daisy-chaining across drop cables is not
permitted** (i.e., you cannot connect a spur cable into Display 1 and
daisy-chain a spur cable out of Display 1 into Display 2, unless the display
integrates a certified internal 2-port active CAN hub/repeater). However, there
are two proven, standard-compliant engineering approaches to achieve a single
cable run:

#### Option A: Multi-Port Drop Box / Splitter (Consolidated Spur Topology)

A passive multi-port distribution block (such as the [Maretron Micro Multi-Port
Box][ref-maretron-multiport] or [Actisense QNB-1 /
SBN-2][ref-actisense-multiport]) is mounted inside the cockpit instrument pod.

```
Main Backbone Trunk (Below Deck)
       |
     [ T-Piece ]
       |
       | <--- Single "Homerun" Spur Cable (Max 6 m total drop path)
       |
+------v------------------------------------+
|  Cockpit Pod Multi-Port Box (Inside Pod)  |
|   [Port 1]        [Port 2]       [Port 3] |
+------|---------------|--------------|-----+
       | (Short drop)  | (Short drop) | (Short drop)
       v               v              v
  [Display 1]     [Display 2]    [Display 3]
```

* **Wiring Mechanics:** A single micro spur cable runs from a T-connector on
  the main backbone through the cockpit coaming into the pod, connecting to the
  input of the multi-port box. Short jumper drops (typically 0.3 m to 1 m)
  connect each of the 3 displays to the individual female drop ports of the
  box.
* **Length Constraints:** The entire distance from the main trunk T-connector,
  through the homerun cable, through the multi-port box, and along the
  individual drop to the instrument must not exceed the **6-meter (20 ft)
  individual drop limit**. Furthermore, each drop contributes to the
  network-wide 78 m cumulative spur limit.

#### Option B: Extending the Backbone into the Pod (Recommended for Long Runs)

If the cable run from the cabin to the cockpit pod is long (or if the pod is
near one end of the boat), the best engineering practice is to route the
**backbone itself** into the cockpit pod:

```
Method B1: Terminated Backbone End in Cockpit Pod
Main Backbone (Cabin) ========> [Backbone Cable into Pod]
                                        |
+---------------------------------------v----------------------------------+
| Inside Cockpit Pod: Multi-T Cluster or Raymarine 5-Way Block (A06064)    |
|                                                                          |
|   Backbone IN ---> [T-1] ========> [T-2] ========> [T-3] ---> [120R Term]|
|                     |               |               |                    |
|                [Display 1]     [Display 2]     [Display 3]               |
+--------------------------------------------------------------------------+
```

* **Wiring Mechanics:**
  1. The single cable routed into the pod is a **backbone trunk cable** (blue
     SeaTalkng or standard Micro-C backbone).
  2. Inside the pod, connect a 5-way junction block (such as the [Raymarine
     SeaTalkng 5-Way Connector A06064][ref-raymarine-5way] or a 4-drop micro
     tee-block).
  3. The incoming backbone connects to one backbone port.
  4. The second backbone port is fitted with a **$120\,\Omega$ backbone
     terminator plug**, terminating that end of the network cleanly inside the
     pod.
  5. The 3 instrument displays connect to the white spur ports using short
     spurs (0.4 m to 1 m).
* **Engineering Advantages:** This approach eliminates spur length restrictions
  for the run up to the cockpit (since backbone runs can extend up to 100
  meters on Micro cable), avoids stub reflections, and preserves the 78 m spur
  budget for other sensors on the vessel.

## 2. Electrical Signaling, Voltage Levels, and Differential CAN

NMEA 2000 operates at a fixed communication speed of **250 kbps** (kilobits per
second).

### 2.1 Differential Signaling (ISO 11898-2)

Unlike single-ended serial links (e.g., SeaTalk1 yellow wire or RS-232), CAN
bus uses a balanced, differential transmission line composed of two wires:
`CAN_H` (White) and `CAN_L` (Blue). Differential signaling cancels out
common-mode electromagnetic noise (EMI) induced by alternators, starter motors,
and marine inverters.

The receiver evaluates the differential voltage across the bus:

$$V_{\text{diff}} = V_{\text{H}} - V_{\text{L}}$$

```
   Voltage
     ^
3.5V |                  +-------------------+ (CAN_H)
     |                  |                   |
2.5V |-----[Recessive]--+-------------------+------[Recessive]--
     |                  |                   |
1.5V |                  +-------------------+ (CAN_L)
     |
  0V +----------------------------------------------------------> Time
          Logic 1             Logic 0              Logic 1
        (Recessive)          (Dominant)          (Recessive)
```

The bus defines two discrete electrical logic states:

1. **Recessive State (Logical 1 / Bus Idle):**
   * Neither CAN_H nor CAN_L is driven by transmitters.
   * Both lines sit at an identical intermediate bias voltage: $V_{\text{H}}
     \approx 2.5\,\text{V}$ and $V_{\text{L}} \approx 2.5\,\text{V}$.
   * The differential voltage is: $$V_{\text{diff}} = 2.5\,\text{V} -
     2.5\,\text{V} = 0\,\text{V}$$ *(Specification window: $-0.5\,\text{V} \le
     V_{\text{diff}} \le +0.05\,\text{V}$)*.
   * When no node is transmitting, pull-up/pull-down bias circuitry inside CAN
     transceivers keeps the bus in this recessive state.
2. **Dominant State (Logical 0 / Active Assertion):**
   * Transceiver output stages actively drive the lines in opposite directions:
     $V_{\text{H}}$ rises to $\approx 3.5\,\text{V}$ while $V_{\text{L}}$ drops
     to $\approx 1.5\,\text{V}$.
   * The differential voltage is: $$V_{\text{diff}} = 3.5\,\text{V} -
     1.5\,\text{V} = +2.0\,\text{V}$$ *(Specification window: $+1.5\,\text{V}
     \le V_{\text{diff}} \le +3.0\,\text{V}$)*.
   * In any conflict on the bus, **Dominant (0) overwrites Recessive (1)**.

### 2.2 Role of 120-Ohm Termination Resistors

The characteristic impedance of standard NMEA 2000 / DeviceNet cable is $Z_0 =
120\,\Omega$. When a high-speed $250\,\text{kbps}$ digital pulse travels down a
copper transmission line, it will reflect back from the end of the cable if it
encounters an open circuit (impedance mismatch). These reflected waves
interfere constructively and destructively with subsequent data edges,
corrupting CAN frame bits.

To eliminate transmission line reflections, a non-inductive $120\,\Omega$
($1/4\,\text{W}$) termination resistor is placed across CAN_H and CAN_L at each
extreme end of the backbone.

Electrically, the two $120\,\Omega$ terminators sit in parallel across the data
lines: $$R_{\text{bus}} = \frac{R_1 \times R_2}{R_1 + R_2} = \frac{120 \times
120}{120 + 120} = 60\,\Omega$$

### 2.3 Diagnostic Resistance and Multimeter Measurements

Field troubleshooting of an NMEA 2000 bus can be carried out with a standard
digital multimeter:

* **Bus Resistance Test (Power OFF):**
  * Disconnect DC power from the backbone.
  * Measure resistance between Pin 4 (CAN_H / White) and Pin 5 (CAN_L / Blue).
  * **Expected Reading: $60\,\Omega$ (nominal, typically $58\,\Omega$ to
    $62\,\Omega$).**
  * If the reading is $\mathbf{120\,\Omega}$, one terminator is missing,
    damaged, or disconnected by a broken backbone cable.
  * If the reading is $\mathbf{40\,\Omega}$, three terminators are connected
    (common error when an internal auto-terminator or extra terminator plug is
    accidentally added).
  * If the reading is $\mathbf{\infty}$ (Open), both terminators are missing or
    the test point is disconnected.
  * If the reading is $\mathbf{0\,\Omega}$, CAN_H and CAN_L are physically
    shorted.
* **Bus DC Bias Voltage Test (Power ON):**
  * Measure DC voltage between Pin 3 (NET-C / Black) and Pin 4 (CAN_H / White):
    typically reads **$2.6\,\text{V}$ to $2.8\,\text{V}$ DC**.
  * Measure DC voltage between Pin 3 (NET-C / Black) and Pin 5 (CAN_L / Blue):
    typically reads **$2.2\,\text{V}$ to $2.4\,\text{V}$ DC**.
  * Measure DC voltage between Pin 3 (NET-C / Black) and Pin 2 (NET-S / Red):
    must read between **$11.5\,\text{V}$ and $14.5\,\text{V}$ DC**.

## 3. CAN 2.0B Frame Mechanics and Bitwise Arbitration

NMEA 2000 uses the **CAN 2.0B Extended Frame** format defined by [ISO
11898-1][ref-iso-11898-1] and [SAE J1939-21][ref-sae-j1939-21]. Extended frames
feature a 29-bit identifier rather than the standard 11-bit identifier of basic
automotive CAN.

### 3.1 Extended 29-Bit Identifier Mapping

The 29-bit identifier does not represent a physical device address alone; it
encapsulates message priority, Parameter Group Number (PGN), destination
address, and source address:

```
Bit: 28   26 25 24 23                 16 15                  8 7                 0
    +-------+--+--+---------------------+---------------------+-------------------+
    |  Prio |R |DP|      PF (PDU Format)|    PS (PDU Specific)| Source Addr (SA)  |
    +-------+--+--+---------------------+---------------------+-------------------+
     3 bits  1  1        8 bits                8 bits                8 bits
```

* **Priority (Bits 28–26):** 3-bit field setting transmission precedence from 0
  (highest priority, e.g., steering / emergency control) to 7 (lowest priority,
  e.g., diagnostic logs). Standard navigation data typically uses priority 2 or
  3.
* **Reserved Bit (Bit 25):** Always set to 0.
* **Data Page (Bit 24):** Used in conjunction with PF to expand the PGN address
  space (typically 0 or 1).
* **PDU Format / PF (Bits 23–16):** Determines whether the message is addressed
  to a specific node or broadcast globally:
  * **PDU1 Format ($\text{PF} < 240$ / `0xF0`):** Addressed message. Here, the
    PS field contains the 8-bit Destination Address (DA).
  * **PDU2 Format ($\text{PF} \ge 240$ / `0xF0`):** Broadcast message. Here,
    the PS field contains an 8-bit Group Extension (GE) byte.
* **PDU Specific / PS (Bits 15–8):** Contains either the Destination Address
  (DA) or Group Extension (GE) based on the PF value.
* **Source Address / SA (Bits 7–0):** The 8-bit unique dynamic address of the
  transmitting node ($0$ to $251$, with $252$ to $255$ reserved for diagnostics
  and broadcast).
  * *Transmitter vs. Listener Limit:* Only devices that **transmit** frames
    onto the network require an address claim, limiting the number of
    concurrently emitting nodes on a single N2K segment to 252. In contrast,
    purely passive or listen-only devices (such as read-only diagnostic
    monitors, data loggers, or display repeaters configured without talker
    capability) do not claim an address and do not transmit frames, so their
    number is not bounded by the 252-address limit (though all nodes remain
    subject to total bus electrical load and capacitance limits).

### 3.2 Non-Destructive Bitwise Arbitration (CSMA/NBA)

CAN bus resolves bus contention through **Carrier-Sense Multiple Access with
Non-Destructive Bitwise Arbitration (CSMA/NBA)**:

1. **Bit Transmission Order (MSB First):** On CAN networks conforming to ISO
   11898, the 29-bit identifier is transmitted **Most Significant Bit (MSB)
   first**, starting with Priority Bit 28 and streaming down sequentially to
   Source Address Bit 0.
2. **Carrier Sense:** Devices wait for an idle bus (11 consecutive recessive
   bits) before beginning transmission.
3. **Simultaneous Transmission:** If two devices begin transmitting at the
   exact same clock instant, their start-of-frame bits coincide.
4. **Bitwise Monitoring:** As each node outputs a bit onto the bus, it monitors
   the actual voltage level present on the differential wires.
5. **Collision Resolution:**
   * If Node A transmits a Recessive 1 ($2.5\,\text{V}$ diff) while Node B
     transmits a Dominant 0 ($2.0\,\text{V}$ diff), the dominant state wins.
   * Node A detects that the bus state does not match its transmitted bit
     (senses a 0 when it sent a 1).
   * Node A immediately ceases transmission and drops back to receiver mode.
   * Node B continues transmitting uninterrupted without corrupted data,
     re-transmitting delays, or bus restart overhead.
   * **Rule:** Lower numerical values in the 29-bit identifier represent higher
     priority because their most significant bits contain dominant `0`s earlier
     in the transmission stream.

## 4. Parameter Group Numbers (PGNs) and Data Transport

Data values in NMEA 2000 are grouped into standardized messages called
**Parameter Group Numbers (PGNs)**.

### 4.1 Calculation of PGN from CAN Identifier

The Parameter Group Number (PGN) is an 18-bit integer extracted from the
Extended Data Page (EDP, Bit 25), Data Page (DP, Bit 24), PDU Format (PF, Bits
23–16), and PDU Specific (PS, Bits 15–8) fields of the 29-bit CAN identifier:

* **Bit 25 (EDP - Extended Data Page):** 1 bit (Bit 17 of the 18-bit PGN). In
  standard marine NMEA 2000, EDP is set to `0`.
* **Bit 24 (DP - Data Page):** 1 bit (Bit 16 of the 18-bit PGN). Selects Page 0
  or Page 1.
* **Bits 23–16 (PF - PDU Format):** 8 bits (Bits 15–8 of the 18-bit PGN).
* **Bits 15–8 (PS - PDU Specific):** 8 bits (Bits 7–0 of the 18-bit PGN).

Together, $\text{EDP}\,(1\,\text{bit}) + \text{DP}\,(1\,\text{bit}) +
\text{PF}\,(8\,\text{bits}) + \text{PS}\,(8\,\text{bits}) = 18\,\text{bits}$
total:

* **PDU1 Addressed Format ($\text{PF} < 240$ / `0xF0`):** The PS field contains
  the Destination Address (DA) and is *not* part of the PGN definition (the
  lower 8 bits of the PGN are masked to `0x00`): $$\text{PGN} = (\text{EDP} \ll
  17) + (\text{DP} \ll 16) + (\text{PF} \ll 8)$$
* **PDU2 Broadcast Format ($\text{PF} \ge 240$ / `0xF0`):** The PS field acts
  as a Group Extension (GE) and forms the lower 8 bits of the PGN: $$\text{PGN}
  = (\text{EDP} \ll 17) + (\text{DP} \ll 16) + (\text{PF} \ll 8) + \text{PS}$$

*Example: PGN 128267 (Water Depth)*
* $\text{PGN Decimal} = 128267 = \text{0x01F50B}$ in hexadecimal.
* $\text{EDP} = 0$, $\text{DP} = 1$, $\text{PF} = \text{0xF5} = 245$ (PDU2
  broadcast format), $\text{PS} = \text{0x0B}$.

### 4.2 Single-Frame vs. Multi-Frame Transport Protocols

CAN 2.0B payload frames carry a maximum of **8 bytes of data**. How a message
is transmitted depends on the PGN definition and payload size:

#### Protocol Determination (Static Specification vs. Dynamic Framing)
* **Pre-Defined Transmission Format:** Whether a given PGN is transmitted as a
  **Single-Frame** or **Fast Packet** message is defined by the NMEA 2000
  specification catalog (e.g., in [`canboat.json`][ref-canboat-json]). For
  instance, PGN 127250 (Vessel Heading, 8 bytes) and PGN 128267 (Water Depth, 8
  bytes) are strictly single-frame messages, whereas PGN 129029 (GNSS Position
  Data, up to 51 bytes) is defined as Fast Packet.
* **Dynamic Frame Differentiation:** While the receiver's dictionary knows
  which transport type a PGN uses, a parser can also identify the framing
  mechanics dynamically:
  1. *Single-Frame PGNs:* The CAN data payload carries raw data starting
     directly at Byte 0, with a CAN Data Length Code (DLC) of up to 8 bytes.
  2. *Fast Packet PGNs:* Byte 0 always functions as a protocol header
     containing a 3-bit sequence counter and a 5-bit sub-frame counter. In the
     first frame, Byte 1 explicitly provides the **Total Payload Byte Count**.

#### Multi-Frame Packet Assembly and Verification Rules
Fast Packet multi-frame assembly does not depend on a hard-coded frame count;
instead, it performs dynamic runtime length verification:

1. **Explicit Length Field:** The initial frame (sub-frame counter `00000`)
   carries the total payload size $L$ (in bytes) in Byte 1, followed by 6 bytes
   of payload data.
2. **Deterministic Frame Count Calculation:** Because subsequent frames carry
   up to 7 payload bytes each, the receiver dynamically calculates the exact
   expected number of frames ($N$): $$N = 1 + \left\lceil \frac{L - 6}{7}
   \right\rceil$$ *(For example, if GNSS Position PGN 129029 indicates $L = 43$
   bytes, the receiver knows exactly $1 + \lceil 37 / 7 \rceil = 1 + 6 = 7$
   frames must be received).*
3. **Sequence & Continuity Validation:**
   * Receivers track the 3-bit sequence ID to ensure frames from interleaved
     transmissions are not mixed.
   * Receivers verify that sub-frame counters increment strictly by 1 (`00000`,
     `00001`, `00010`, etc.). If a frame is dropped or arrives out of sequence,
     the entire assembly is immediately aborted.
   * If all $N$ frames (totaling $L$ bytes) are not reassembled within a
     standard timeout window (typically 250 ms to 750 ms), the partial buffer
     is discarded.

## 5. Dynamic Address Claim and Network Management

NMEA 2000 devices do not have fixed, hard-coded network addresses. Instead, the
network implements a dynamic, self-configuring address negotiation system
derived from [SAE J1939-81 Network Management][ref-sae-j1939-81].

### 5.1 The 64-Bit Unique Device NAME

Every certified NMEA 2000 device is programmed at the factory with a globally
unique 64-bit (8-byte) identifier known as the **NAME**:

```
Bit: 63   62             48 47          32 31           21 20           16 15 13 12       0
    +----+-----------------+--------------+---------------+---------------+-----+----------+
    | Arb| Device Class    | Device Func  | Mfr Code      | Unique Inst.  | Ind | Identity |
    | Cap| (7 bits)        | (8 bits)     | (11 bits)     | (5 bits)      | (3b)| Number   |
    +----+-----------------+--------------+---------------+---------------+-----+----------+
```

* **Arbitrary Address Capable (Bit 63):** Set to 1 for marine devices, allowing
  them to select an alternate address if their preferred address is in use.
* **Device Class (Bits 62–56):** Broad equipment category (e.g., `20` = Sensor
  Communication Interface, `25` = Inter/Intranetwork Device, `40` = Steering /
  Autopilot, `60` = Navigation System).
* **Device Function (Bits 47–40):** Specific functionality within class (e.g.,
  heading sensor, depth sensor, GPS receiver).
* **Manufacturer Code (Bits 31–21):** Unique 11-bit code assigned by NMEA to
  the manufacturer (e.g., Raymarine, Garmin, Navico, Maretron).
* **Identity Number (Bits 20–0):** Unique 21-bit serial number ensuring no two
  devices from the same manufacturer have identical NAMEs.

### 5.2 The Address Claim Process

When a device powers up or connects to the backbone:

1. **Transmit Address Claim:** The device selects its preferred address (stored
   in non-volatile EEPROM from previous sessions) and broadcasts an **ISO
   Address Claim (PGN 060928)** containing its 64-bit NAME.
2. **Contention Resolution:**
   * If another device is already operating on that exact same address, both
     devices compare their 64-bit NAMEs treated as an unsigned integer.
   * **Rule: The lower numerical 64-bit NAME wins.**
   * *If the incumbent node has the lower NAME:* It re-broadcasts its Address
     Claim to defend its position. The newly attached higher-NAME node yields,
     increments its address counter (looking for an open address between 0 and
     251), and issues a new Address Claim.
   * *If the newly attached node has the lower NAME:* It claims the address.
     The incumbent node must immediately surrender the address, locate an
     unused address slot, and broadcast a claim for its new address.
3. **Cannot Claim Address (Address 254):** If a device attempts all valid
   addresses (0 to 251) and finds no free slot, it broadcasts an address claim
   with Source Address `254` (Cannot Claim Address / Null Address) and enters a
   passive, non-transmitting state:
   * *MFD Alerts & Diagnostics:* The transmission of an Address Claim from SA
     `254` is an explicit, broadcast network event. Marine Multi-Function
     Displays (MFDs) and network gateways (e.g., Raymarine Axiom, Garmin
     GPSMAP, Navico Zeus) monitor PGN 060928 from all nodes. When an MFD
     detects an address claim from SA `254`, it parses the 64-bit NAME and
     device class in the payload and displays a system alert or diagnostic
     warning (e.g., `"Network Device Address Conflict"`, `"N2K Device Cannot
     Claim Address"`, or `"Device Limit Exceeded"`). Furthermore, the device is
     flagged as offline in the MFD's NMEA 2000 Device List.
   * *Retry & Backoff Mechanics:* Standard J1939-81 / NMEA 2000 rules forbid an
     unsuccessful node from autonomously spamming new address claims in a tight
     loop. Instead, the device remains dormant in listen-only mode. It will
     only re-attempt an address claim under specific triggers:
     1. *Network ISO Address Request (PGN 059904):* If another device (such as
        an MFD or diagnostic tool) broadcasts an ISO Request for PGN 060928,
        the dormant device must respond, re-evaluating bus address occupancy.
     2. *Detection of Address Release:* By monitoring the bus in listen-only
        mode, if the device observes that a previously claimed address has
        become vacant (or if an incumbent node disconnects or drops offline),
        it can initiate a claim for the freed address after a randomized
        backoff period (typically 250 ms to 1250 ms) to avoid collisions with
        other contending nodes.
     3. *Hardware Power Cycle / Bus Reset:* A hardware reboot or DC power reset
        forces the device to clear its contention table and restart the full
        address claim sequence from its default preferred address.

## 6. Power Distribution Rules, LEN Budgeting, and Grounding

Unlike automotive CAN systems where devices power their microprocessors
entirely from dedicated local battery feeds, NMEA 2000 distributes both
communication and operational DC power across the bus cable to energize
low-power sensors and transducers directly.

### 6.1 The Load Equivalency Number (LEN)

To simplify power budgeting without requiring complex electrical calculations
on site, the standard defines the **Load Equivalency Number (LEN)**:
$$1\,\text{LEN} = 50\,\text{mA} \text{ at } 12\,\text{V DC}$$

Every certified device specifies its maximum continuous current draw rounded up
to the nearest whole integer:
* A wind transducer drawing $35\,\text{mA}$ is rated at **1 LEN**
  ($50\,\text{mA}$).
* An electronic fluxgate compass drawing $90\,\text{mA}$ is rated at **2 LEN**
  ($100\,\text{mA}$).
* An instrument display drawing $170\,\text{mA}$ with backlight at 100% is
  rated at **4 LEN** ($200\,\text{mA}$).

### 6.2 Maximum Backbone Voltage Drop and Power Sizing

According to the [Garmin NMEA 2000 Technical Reference][ref-garmin-n2k] and
[Actisense Power Guidelines][ref-actisense-power], the operational voltage
range for NMEA 2000 equipment is **9.0V to 16.0V DC** (nominal 12V):

* **The 1.67V Maximum Drop Rule:** Across the entire length of the backbone
  from the power injection tap to the furthest device, the total cumulative
  voltage drop ($\Delta V = I \times R$) on the power conductors must **never
  exceed 1.67 Volts** under maximum full-load conditions.
* Starting with a fully charged marine battery bank at $12.6\,\text{V}$, an
  acceptable $1.67\,\text{V}$ drop ensures that the most distant node receives
  at least $10.93\,\text{V}$, well above the $9.0\,\text{V}$ shutdown
  threshold.

### 6.3 Power Injection Insertion Methods

There are two primary methods for injecting DC power into an NMEA 2000
backbone:

```
Method A: End Power Insertion
+--[12V Tap]=======[T]=======[T]=======[T]=======[T]=======[120R]
(All devices must fit within 1.67V drop window over length L)

Method B: Center Power Insertion (Recommended for larger networks)
[120R]=======[T]=======[T]====[12V Tap]====[T]=======[T]=======[120R]
|<--- 50% Load Left ------>|           |<--- 50% Load Right ---->|
```

1. **Center Power Feed:** Placing the 12V power insertion tap in the physical
   center of the backbone halves the effective cable distance to both ends,
   reducing line resistance by 50% and doubling allowable current capacity
   relative to an end feed.
2. **Single Power Source Rule:** An NMEA 2000 network must only have **one** DC
   power insertion tap unless isolated power-isolating T-connectors are used.
   Connecting multiple un-isolated 12V supplies risks circulating ground
   currents, back-feeding breakers, and fire hazards.
3. **High-Draw Equipment Isolation:** High-amperage equipment (such as
   chartplotters, radar scanners, sonar sounder modules, and autopilot
   actuators) must connect to their own independent battery circuits and draw 0
   LEN from the backbone, using opto-isolated internal transceivers to connect
   to CAN_H / CAN_L.

### 6.4 Grounding and RF Shielding

* **Single-Point Ground Rule:** The network shield drain wire (Pin 1) must be
  connected to the vessel's primary RF ground or negative battery bus bar at
  **exactly one physical point**, typically directly at the power insertion
  tap.
* Grounding the shield at multiple points creates closed ground loops that
  induce alternator hum and RF interference into the differential data lines.

## 7. Interfacing NMEA 2000 with PCs, SBCs, and Microcontrollers

Modern marine navigation architectures frequently integrate NMEA 2000 data into
open-source marine computers running [Signal K][ref-signalk-main] or
[OpenPlotter][ref-openplotter-docs], chartplotters running
[OpenCPN][ref-opencpn-main], or embedded microcontrollers (ESP32, STM32).

### 7.1 Hardware Interface Bridges

Because standard computers and microcontrollers lack direct CAN bus marine
transceivers, intermediate hardware bridges are required:

1. **USB-to-CAN Bridges (CDC ACM & Virtual COM):**
   * Commercial gateways such as the [Yacht Devices YDNU-02][ref-ydnu-02]
     convert bidirectional NMEA 2000 CAN frames into serial data streams over
     USB.
   * Supports raw binary streaming, Actisense NGT-1 format, or converted NMEA
     0183 ASCII text.
2. **Wi-Fi & Ethernet Gateways:**
   * Devices like the [Yacht Devices YDWG-02][ref-ydwg-02] broadcast NMEA 2000
     data via TCP/UDP sockets to tablets running Navionics, Aqua Map, or Signal
     K.
3. **SocketCAN Interfaces (Linux / Raspberry Pi):**
   * Hardware CAN controllers (such as the Microchip MCP2515 via SPI or native
     CAN on modern compute modules) bind directly into the Linux kernel using
     [SocketCAN][ref-socketcan-docs].
   * Creates a native network interface (e.g., `can0`) operating with standard
     Linux networking tools (`candump`, `cansend` from `can-utils`).

### 7.2 Microcontroller Circuit (ESP32 Native TWAI)

The ESP32 microcontroller features an integrated CAN controller (designated the
**Two-Wire Automotive Interface / TWAI**), requiring only an external 3.3V CAN
transceiver (such as the [Texas Instruments SN65HVD230][ref-ti-sn65hvd230]):

```
 +------------------+                 +----------------------+
 |                  |  TWAI_TX (GPIO) |                      |
 |  ESP32 MCU       |---------------->| TXD     SN65HVD230   |==== CAN_H (White)
 |                  |<----------------| RXD    3.3V CAN XCVR |==== CAN_L (Blue)
 |                  |  TWAI_RX (GPIO) |                      |
 |                  |                 | GND              GND |----+
 +------------------+                 +----------------------+    |
         |                                                        |
         +--------------------------------------------------------+ (0V Common)
```

Open-source libraries like [Timo Lappalainen's NMEA2000
library][ref-lappalainen-n2k] enable direct transmission and parsing of PGNs on
ESP32, Teensy, and Arduino platforms.

## 8. NMEA 2000 Diagnostic Matrix and Troubleshooting Reference

When commissioning or troubleshooting an NMEA 2000 network, use the following
symptom matrix:

| Observed Symptom | Probable Electrical Root Cause | Verification Step / Solution |
| :--- | :--- | :--- |
| **All instruments lose data periodically** | Bus resistance incorrect or missing terminator | Measure bus resistance between CAN_H and CAN_L with power off. Must read $60\,\Omega$. |
| **Random PGN packet dropouts / CRC errors** | Spur length exceeds 6 m or total spur exceeds 78 m | Audit spur run lengths. Shorten long drops using backbone T-connectors. |
| **Devices crash when backlights turn on** | Excessive voltage drop on power lines ($\Delta V > 1.67\,\text{V}$) | Measure DC voltage under load at terminal node. Reconfigure power tap to center. |
| **Multimeter reads $120\,\Omega$ bus resistance** | One termination resistor missing or broken cable | Inspect both ends of the backbone. Verify both $120\,\Omega$ terminators are installed. |
| **Multimeter reads $40\,\Omega$ bus resistance** | Three termination resistors installed | Locate and remove the third terminator (check for internal terminator switch on MFD). |
| **High CAN error frame counter (`can0`)** | CAN_H and CAN_L inverted or shield ground loop | Verify white wire to CAN_H and blue wire to CAN_L. Verify shield is grounded at 1 point. |
| **Node reports "Address Claim Collision"** | Duplicate 64-bit NAME or exhausted addresses | Inspect node configuration. Power cycle network to force dynamic re-arbitration. |
